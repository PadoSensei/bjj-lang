# Coding Standards

- TypeScript strict mode.
- Avoid `any`; if unavoidable, isolate and explain.
- Prefer small, named functions and explicit domain types.
- Validate untrusted input at boundaries with Zod.
- Keep UI components focused and accessible.
- Use consistent error/loading/empty states.
- No business logic in screens.
- No secret values in source or logs.
- Do not suppress lint/type errors without a documented reason.
- Tests should assert behavior, not implementation details.
- Follow established repository patterns before adding abstractions.
