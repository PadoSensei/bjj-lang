# Vercel Deployment Guide

This guide describes how to configure, preview, and deploy BJJ_Lang on Vercel using the existing Expo Router and React Native Web stack.

## Architecture and Build Overview

BJJ_Lang uses Expo Router with Metro web export. The production build generates a static Single Page Application (SPA) in the `dist` directory:
- `index.html`: Base HTML template and mounting point (`#root`).
- `_expo/static/js/web/`: JavaScript bundles generated by Metro bundler.
- `assets/`: Static image and media assets.

To support client-side deep linking and direct page refreshes (such as `/select-direction`, `/review`, or `/lesson/[id]`), all requests not matching static assets are rewritten to `/index.html` via `vercel.json`.

## Prerequisites

- **Node.js**: `22.x` (or newer LTS)
- **pnpm**: `10.30.3` (pinned in `package.json` under `packageManager`)

## Local Development & Production Web Export

### 1. Local Web Development Server

To run the local development server with hot module replacement:

```bash
pnpm web
```

This runs `expo start --web` using Metro.

### 2. Building the Production Web Export Locally

To generate the static production export locally:

```bash
pnpm run build:web
```

This executes `expo export -p web`, outputting static files into the `dist` directory.

### 3. Inspecting the Production Export Locally

You can preview the exported production files with any local HTTP server supporting SPA rewrites:

```bash
npx serve -s dist
```

Alternatively, with Python:
```bash
python3 -c "
import http.server, socketserver, os
DIR = os.path.abspath('dist')
class SPAHandler(http.server.SimpleHTTPRequestHandler):
    def __init__(self, *args, **kwargs):
        super().__init__(*args, directory=DIR, **kwargs)
    def translate_path(self, path):
        t = super().translate_path(path)
        return t if os.path.exists(t) else os.path.join(DIR, 'index.html')
socketserver.TCPServer.allow_reuse_address = True
with socketserver.TCPServer(('', 3000), SPAHandler) as httpd:
    print('Serving dist at http://localhost:3000')
    httpd.serve_forever()
"
```

Verify that navigating directly to `/`, `/select-direction`, `/review`, and `/lesson/lesson-1-1` correctly serves the app and loads static assets.

## Vercel Project Configuration

The repository includes a root `vercel.json` file configuring the build and rewrites:

```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "framework": null,
  "buildCommand": "pnpm run build:web",
  "outputDirectory": "dist",
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

### Exact Vercel Dashboard Settings

When importing the repository into the Vercel Dashboard:

| Setting | Value | Notes |
| --- | --- | --- |
| **Framework Preset** | `Other` (or null) | Expo web produces static assets in `dist` |
| **Root Directory** | `./` (leave empty/default) | Repository root |
| **Build Command** | `pnpm run build:web` | Or toggle default (reads from `vercel.json`) |
| **Output Directory** | `dist` | Generated by `expo export -p web` |
| **Install Command** | `pnpm install --frozen-lockfile` | Ensures lockfile-pinned reproducible installs |
| **Node.js Version** | `22.x` | Set under Project Settings -> General -> Node.js Version |

## GitHub Integration & Deployment Environments

### Preview Deployments (Pull Requests)
- Every pull request opened against `master` automatically triggers a Vercel Preview Deployment.
- Preview deployments run isolated builds with unique preview URLs.
- **Preview builds require zero manual environment variables**: the app initializes with safe defaults out of the box.

### Production Deployments (Base Branch)
- Merges or pushes to the `master` branch trigger production deployments to the primary domain.

## Environment Variables & Safe Management

### Required Environment Variables

**No environment variables are required** for the app to build or run. The client environment schema (`src/config/env.ts`) treats all variables as optional with safe fallback defaults:

- `EXPO_PUBLIC_APP_ENV`: defaults to `'development'`. Can be overridden to `'preview'` or `'production'` in Vercel project environment variables.
- `EXPO_PUBLIC_SUPABASE_URL`: optional.
- `EXPO_PUBLIC_SUPABASE_ANON_KEY`: optional.

### Safe Environment Variable Guidelines

1. **Client-side variables must use the `EXPO_PUBLIC_` prefix**:
   - Variables prefixed with `EXPO_PUBLIC_` are inlined into the client bundle at build time.
2. **Never expose secrets**:
   - Never prefix sensitive keys (such as `SUPABASE_SERVICE_ROLE_KEY`, private tokens, or administrative credentials) with `EXPO_PUBLIC_`.
   - Never commit `.env` or production credentials to git.
3. **Configure in Vercel**:
   - Add environment variables in Vercel under **Project Settings -> Environment Variables**.
   - Select the target environments (`Production`, `Preview`, `Development`).

## Known Differences Between Web and Native Builds

1. **Storage Persistence**:
   - Native builds (iOS/Android) use SQLite-backed AsyncStorage.
   - Web builds use browser `localStorage` wrapped by `@react-native-async-storage/async-storage`. Ensure private browsing / restricted cookie settings do not block `localStorage`.
2. **Navigation & Deep Linking**:
   - Web navigation uses standard browser URL history and paths (`window.location.pathname`).
   - Native navigation relies on deep linking schemes (`bjj-lang://`).
3. **CSS and Styling**:
   - React Native Web maps React Native components (`View`, `Text`, `Pressable`) to DOM elements (`<div>`, `<span>`).
   - Reset styles in `dist/index.html` ensure full-height flex layout (`#root`).

## Common Deployment Errors & Troubleshooting

1. **404 Not Found on Route Refresh or Direct Link**:
   - *Cause*: Missing SPA rewrite rule.
   - *Fix*: Ensure `vercel.json` includes the SPA rewrite rule (`"source": "/(.*)", "destination": "/index.html"`).
2. **Lockfile Mismatch / Install Failure**:
   - *Cause*: Modifying `package.json` without updating `pnpm-lock.yaml`.
   - *Fix*: Always use `pnpm install --frozen-lockfile` and commit updated lockfiles when dependencies change.
3. **Node.js Engine Incompatibility**:
   - *Cause*: Vercel project defaulted to an older Node.js version (e.g. Node 18 or 20).
   - *Fix*: In Vercel Project Settings -> General, ensure the Node.js version is set to `22.x`.
4. **Environment Validation Error at Startup**:
   - *Cause*: Invalid URL format supplied to `EXPO_PUBLIC_SUPABASE_URL`.
   - *Fix*: Ensure environment variables conform to the schema defined in `src/config/env.ts`.
